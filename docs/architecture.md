# Как работает TagCleaner

## Приложение и обработка файлов

[`desktop.py`](../desktop.py) открывает окно pywebview с WebView2. [`gui.py`](../gui.py) обслуживает HTML-интерфейс на `127.0.0.1` и передаёт команды отдельному процессу [`ui/worker.py`](../ui/worker.py). Команды и события передаются в JSON. Для операций через локальный HTTP используется токен сессии. Вариант `TagCleaner.cmd --browser` открывает тот же интерфейс в браузере.

[`core/scanner.py`](../core/scanner.py) читает заголовки и теги через Mutagen. Анализ отделён от записи. Выбор издания и предложения опираются на сведения о записи, исполнителе, версии, длительности и релизе. RapidFuzz помогает сравнивать строки. Слабые или конфликтующие данные могут требовать ручной проверки.

## Распознавание и каталоги

| Инструмент | Назначение |
| --- | --- |
| FFmpeg и ffprobe | Декодирование, извлечение аудиофрагментов и проверка длительности. |
| Chromaprint (`fpcalc`) и AcoustID | Локальное вычисление отпечатка. Запрос по отпечатку и длительности требует `ACOUSTID_API_KEY`. |
| ShazamIO | Поиск по коротким фрагментам. Доступность зависит от сервиса, ключ для обычного использования не требуется. |
| MusicBrainz и iTunes Search | Поиск по текстовым данным и уточнение сведений об изданиях. |
| ACRCloud и AudD | Дополнительное распознавание при наличии настроенных учётных данных. |
| Discogs и Last.fm | Дополнительные каталоги при настройке токена или ключа. |

Приложение переиспользует локальные результаты и регулирует частоту запросов. Чтобы подключить дополнительный сервис, добавьте нужные переменные в `.env` рядом с `TagCleaner.cmd` и перезапустите приложение. Используйте `ACOUSTID_API_KEY` для AcoustID, `ACRCLOUD_HOST`, `ACRCLOUD_ACCESS_KEY` и `ACRCLOUD_ACCESS_SECRET` для ACRCloud, `AUDD_API_TOKEN` и `TAGCLEANER_AUDD=1` для AudD, `DISCOGS_TOKEN` для Discogs или `LASTFM_API_KEY` для Last.fm. `TAGCLEANER_SHAZAM=0` отключает Shazam. Держите `.env` у себя.

Отпечатки или фрагменты передаются сервисам при выполнении соответствующего способа распознавания. Запросы по каталогам используют текстовые данные.

## Поиск и запись обложек

[`core/cover_search.py`](../core/cover_search.py) запрашивает Apple Music и MusicBrainz с Cover Art Archive. В зависимости от запроса и настроек также могут использоваться Deezer, SoundCloud, Discogs и Last.fm. Поддерживаемые ссылки на страницы релизов обрабатывает [`core/cover_pages.py`](../core/cover_pages.py). Поиск по нескольким источникам идёт параллельно. При пакетной подготовке повторяющиеся запросы и загрузки переиспользуются.

Для вариантов сравниваются исполнитель, версия названия и длительность. Совпадение картинки с источником означает, что пиксели одинаковы и данные записи согласуются. Конкретное издание по этому признаку установить нельзя. Изображения проверяются через Pillow. По выбору пользователя OpenCV и FSRCNN увеличивают маленькие обложки, а Pillow выполняет преобразование размера и обрезку 1:1.

Очередь сохраняет выбранную картинку и параметры обработки в SQLite. Перед записью приложение сверяет состояние файла с моментом выбора и создаёт резервную копию. После записи перечитывает изображение и текстовые теги. При неудачной записи приложение пытается восстановить оригинал и оставляет запись в очереди.

## Данные на диске

| Папка | Содержимое |
| --- | --- |
| `config` | Настройки и последний набор файлов. |
| `cache` | Ответы сервисов, изображения, отпечатки и промежуточные результаты. |
| `ui_runtime` | Очередь, история, черновики и локальные снимки библиотеки. |
| `backups` | Копии файлов, изменённых приложением. |
| `reports` | Отчёты приложения. |
| `runtime` и `.venv-audio` | Загрузчик, локальный Python, пакеты и инструменты для аудио. |
